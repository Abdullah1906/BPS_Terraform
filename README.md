## What was added

- Existing API Gateway + VPC Link + internal ALB architecture retained.
- .NET 8 runtime on ASG instances.
- EC2 Auto Scaling Group:
  - min 2
  - desired 2
  - max 4
  - private subnets
  - CPU target tracking at 60%
- SQL Server EC2:
  - Ubuntu 22.04
  - SQL Server 2022 Developer
  - private subnet
  - 100 GB gp3 encrypted root disk
  - port 1433 allowed only from the BPS application security group
- AWS Secrets Manager:
  - randomly generated SA password
  - application instances read the secret using IAM
- Private S3 deployment artifact bucket.
- GitHub Actions OIDC role: no long-lived AWS access key is required.
- GitHub Actions:
  - restore
  - build
  - publish
  - zip
  - upload to S3
  - SSM deploy to every ASG instance tagged Project=bps and Role=api
  - restart bps-api systemd service
- Minimal `src/BPS.Api` project is included as a deployment smoke-test.
  Replace it with your real BPS Clean Architecture API before production use.

## SQL Server licensing

The bootstrap uses SQL Server 2022 Developer Edition. Microsoft describes Developer Edition as freely licensed for non-production use. Do NOT use Developer Edition for a production workload; choose the appropriate licensed edition for production.

SQL Server 2022 supports Ubuntu 22.04 starting with CU10. The bootstrap therefore uses Ubuntu 22.04 for the SQL Server host.

## Secrets

The SA password is generated by Terraform and stored in AWS Secrets Manager. The password is not hard-coded into the user-data files.

Important: the generated password is still represented in Terraform state through the random_password/resource graph. Use encrypted remote Terraform state and restrict state access.

## First setup

1. Copy variables:

cp terraform.tfvars.example terraform.tfvars

2. Edit:
- github_org
- github_repo
- github_branch
- region and instance sizes if needed

3. Run:

terraform init
terraform fmt -recursive
terraform validate
terraform plan
terraform apply

4. Get outputs:

terraform output api_gateway_url
terraform output artifact_bucket
terraform output asg_name
terraform output github_actions_role_arn
terraform output sql_private_ip

## GitHub Actions configuration

Open `.github/workflows/deploy.yml`.

Replace:

REPLACE_WITH_TERRAFORM_OUTPUT_ARTIFACT_BUCKET
REPLACE_WITH_TERRAFORM_OUTPUT_ASG_NAME
REPLACE_WITH_TERRAFORM_OUTPUT_GITHUB_ACTIONS_ROLE_ARN

The workflow intentionally uses AWS OIDC instead of storing AWS_ACCESS_KEY_ID/AWS_SECRET_ACCESS_KEY in GitHub.

## Your real BPS API

The included `src/BPS.Api` is only a smoke-test/deployment example.

For your real project, copy your existing Clean Architecture solution into `src/` and make sure the API project:

- targets net8.0
- publishes `BPS.Api.dll`
- listens on `http://0.0.0.0:5000`
- exposes `GET /health`
- reads `ConnectionStrings__DefaultConnection`

The generated connection string is:

Server=<SQL_PRIVATE_IP>,1433;Database=BPS;User Id=sa;Password=<secret>;TrustServerCertificate=True;

Your existing ADO.NET repositories/stored procedures can continue to be used.

## Database initialization

`database/01-create-bps.sql` is only a minimal database creation example.

Put your actual BPS schema and stored procedures into this directory, for example:

database/
  01-create-bps.sql
  02-places.sql
  03-users.sql
  04-trip-records.sql
  05-stored-procedures.sql

Run those scripts against the private SQL Server through SSM or a controlled migration job.

## Important production changes

1. Replace API Gateway CORS `*` with the real Angular domain.
2. Add an API Gateway custom domain + ACM certificate.
3. Add JWT/Cognito/custom authorization as appropriate.
4. Use SQL Server Standard/Enterprise or another correctly licensed production edition instead of Developer.
5. Add automated SQL backups and test restore procedures.
6. Consider a separate encrypted EBS data volume for SQL Server database files rather than putting all database data on the root volume.
7. Consider Multi-AZ SQL architecture/RDS for SQL Server if the availability requirement justifies it.
8. Keep SQL Server private; never open 1433 to the internet.
9. Keep EC2 private; use SSM instead of public SSH.
10. Use S3 remote Terraform state with state locking.
11. For production, consider one NAT Gateway per AZ for higher availability.
12. Add CloudWatch logs/metrics/alarms.
13. For zero-downtime deployment, use ASG instance refresh/rolling replacement or a blue/green strategy rather than restarting every instance simultaneously.

## SQL Server installation reference

The SQL bootstrap follows Microsoft's unattended-install pattern using:
- MSSQL_PID
- ACCEPT_EULA
- MSSQL_SA_PASSWORD
- `mssql-conf -n setup`

See Microsoft SQL Server Linux documentation for supported versions and installation details.
